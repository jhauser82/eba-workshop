## Code Changes Required

### 1. Remove hard-coded fallback credentials — `Services/DatabaseInitializer.cs`
- **File**: `Services/DatabaseInitializer.cs`
- **Method**: `GetConnectionString`
- Replace nullable-coalesce fallbacks with exceptions so the app fails fast when credentials are missing rather than connecting with a default password:
  ```csharp
  // Replace:
  var user = Environment.GetEnvironmentVariable("DB_USER") ?? "root";
  var pass = Environment.GetEnvironmentVariable("DB_PASSWORD") ?? "password";

  // With:
  var user = Environment.GetEnvironmentVariable("DB_USER")
      ?? throw new InvalidOperationException("DB_USER environment variable is not set.");
  var pass = Environment.GetEnvironmentVariable("DB_PASSWORD")
      ?? throw new InvalidOperationException("DB_PASSWORD environment variable is not set.");
  ```

### 2. Fix hard-coded port binding — `Program.cs`
- **File**: `Program.cs`
- Remove the `UseUrls("http://0.0.0.0:80")` call. Replace it with a port-agnostic alternative that respects the standard .NET 8+ environment variable:
  ```csharp
  // Replace:
  .UseUrls("http://0.0.0.0:80")

  // With:
  .UseUrls(Environment.GetEnvironmentVariable("ASPNETCORE_HTTP_PORTS") is { } p
      ? $"http://0.0.0.0:{p}"
      : "http://0.0.0.0:8080")
  ```
- **Alternative**: Delete the `UseUrls(...)` call entirely and set `ASPNETCORE_HTTP_PORTS=8080` in the deployment environment (Docker Compose, Kubernetes manifest, etc.).

## Deployment Considerations

- **.NET 10 container images run as a non-root user** (`app`, UID 1654). Binding to port 80 requires root privileges and will fail silently. Use port 8080 (or any port ≥ 1024) and update any reverse-proxy or load-balancer rules (e.g., nginx `proxy_pass`, AWS ALB target group) to target port 8080.
- **`ASPNETCORE_HTTP_PORTS`** is the preferred .NET 8+ mechanism for controlling the listening port inside containers. Inject it via the Docker Compose `environment:` block or a Kubernetes `env:` entry rather than hard-coding it in source.
- **MySQL 26.10.0 SSL defaults**: The connector now defaults to `SslMode=Preferred` and `caching_sha2_password`. Ensure the MySQL server version and user authentication plugin are compatible, and that the deployment environment permits the required SSL handshake (certificates, firewall rules).
- **Secrets management**: `DB_HOST`, `DB_USER`, `DB_PASSWORD`, and `DB_NAME` must be injected at runtime via environment variables or a secrets manager (e.g., AWS Secrets Manager, Azure Key Vault, Kubernetes Secrets). Audit all Docker Compose files and CI/CD pipeline definitions to confirm no literal credentials are committed to source control.

**What deploys:** web, worker and console projects. Class libraries and test projects are not deployed. WinForms and WPF apps can't run in Linux containers, so skip this step for them. A console app that runs once and exits deploys as an ECS task or a Kubernetes Job, not a long-running service.

Give the prompt below to your coding assistant (Kiro, Claude Code, or another MCP client). It uses the AWS Transform MCP server and the **Source Code Containerization** agent (`vmware-containerization-agent`). That agent builds the image, pushes it to Amazon ECR, generates Terraform or Helm, and deploys to **Amazon ECS or EKS**. For EC2, Elastic Beanstalk or Lambda, stop after Publish Images and deploy the ECR image yourself.

### Setup (once)
- Claude Code: `claude mcp add aws-transform -e AWS_PROFILE=<profile> -- uvx awslabs.aws-transform-mcp-server@latest`
- Kiro: add to `~/.kiro/settings/mcp.json`:
  `{"mcpServers":{"aws-transform":{"command":"uvx","args":["awslabs.aws-transform-mcp-server@latest"],"env":{"AWS_PROFILE":"<profile>"}}}}`
- `AWS_PROFILE` is optional. Without it, the assistant signs in with IAM Identity Center, which opens a browser.
